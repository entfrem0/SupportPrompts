## 日付, 日時型の例

ここでは前提と実現したい処理内容とEL式の記述例を掲載します。

### 1. 日付型：申請日から週明けを求めたい

#### 質問

```
ワークフローアプリには、以下のデータ項目がある。

申請日
　変数型：日付型
　フィールド名：q_application_date

受付期限
　変数型：日付型
　フィールド名：q_deadline


「受付期限」の値を、「申請日の週明け」に更新したい。
```



説明：日付型データを別の日付型に変換する処理です。他のメソッドについても同様の手順で対応します。


#### 回答

```
EL式：#q_application_date?.addDays(7)?.getFirstDateInWeek()

#q_application_date 日付型

設定対象のデータ項目: q_deadline 日付型
```

### 2. 日付型：営業日計算をしたい

#### 質問

```
ワークフローアプリには、以下のデータ項目がある。

契約開始日
　変数型：日付型
　フィールド名：q_contract_start

契約終了日
　変数型：日付型
　フィールド名：q_contract_end


「契約終了日」の値を、「契約開始日から3営業日後」に更新したい。
```

説明：この例は、ユーザーの要望が実現できない場合のパターンを示しています。

#### 回答

```
「契約開始日から3営業日後」の「営業日」を計算する関数は存在しない。
```

### 3. 日時型：日数＋時刻を指定したい

#### 質問

```
ワークフローアプリには、以下のデータ項目がある。

修理受付の日
　変数型：日時型
　フィールド名：q_repair_acceptdate

修理完了予定日時
  変数型：日時型
　フィールド名：q_repair_due 

修理完了予定日を、受付から12日後の午後6時に設定したい。
```

説明：
 - 更新対象が日付型の場合、日時型に変換することで時刻の操作が可能になります。
 - ユーザーの指定したデータ型が適切でないと判断される場合には、改善案も提示します。

#### 回答

```
EL式：#q_repair_acceptdate?.addDays(12)?.getFirstTimeInDate()?.addHours(18)

設定対象のデータ項目: q_repair_due 日時型
```

### 4. システム日時から計算したい

#### 質問

```
ワークフローアプリには、以下のデータ項目がある。

プロジェクト締め切りの日時
　変数型：日時型
　フィールド名：q_duetime

締め切りをプロセス開始後一週間後の0時に設定したい。
```

説明：processInstanceStartDatetime、#today、#now のようなシステム設定書式を使う場合に限り、セーフナビゲーション演算子（?.）は不要です。

#### 回答

```
EL式：processInstanceStartDatetime.addDays(7).getFirstTimeInDate()

processInstanceStartDatetime 日時型（プロセス開始日時）

設定対象のデータ項目: q_duetime
```

### 5. 直近の金曜日を日付型で求めたい

#### 質問

```
ワークフローアプリには、以下のデータ項目がある。

プロジェクト開始日
　変数型：日付型
　フィールド名：q_start_date

プロジェクト開始日を今日より直前の金曜日に設定したい。
```

説明：数日を加算して、現在の日付が金曜日より前か後かを判断する
　
#### 回答

```
EL式：#today?.addDays(2)?.getFirstDateInWeek()?.addDays(-3)

設定対象のデータ項目: q_start_date 日付型
```

### 6. 日付型→日時型：月末の指定時刻にしたい

#### 質問

```
ワークフローアプリには、以下のデータ項目がある。

入社日
　変数型：日付型
　フィールド名：q_hire_date

試用期間終了日時
　変数型：日時型
　フィールド名：q_trial_endtime

試用期間終了日時を、入社2ヶ月後末日、午前10時に設定したい。
```

説明：
 - この例では、日付型と日時型の相互変換および、それぞれに適用できるメソッドについて説明しています。
 - 要望に時間情報が含まれているため、設定対象のデータ項目は日時型である必要があります。

#### 回答

```
EL式：#q_hire_date?.addMonths(2)?.getLastDateInMonth()?.getFirstTimeInDate()?.addHours(10)

設定対象のデータ項目: q_trial_endtime
```

説明：入力が日付型の場合、.getFirstTimeInDate() を使って日時型に変換する必要があります。

### 7. UTCから「現地日付の0時」を計算したい

#### 質問

```

ワークフローアプリには、以下のデータ項目がある。

基準時刻（UTC）
　変数型：日時型
　フィールド名：q_now_utc

次回ローカル0時
　変数型：日時型
　フィールド名：q_next_local_midnight

要件：ユーザーのタイムゾーンやUTCオフセットの項目が存在しない前提で、「次回の現地日付の0:00（ローカル真夜中）」を計算して q_next_local_midnight に設定したい。
```


#### 回答

```
この要件は、単体のEL式（データ更新のEL式）のみでは実現できない。理由：

1. タイムゾーン情報がないため、UTCからローカル時刻への正確な変換ができない。
2. 夏時間（DST）により、地域や時期によって日付境界や0:00の扱いが変化しますが、EL式は外部のタイムゾーン規則にアクセスできない。
3. 文字型データ（タイムゾーンID等）を使わない条件では、少なくとも数値型のUTCオフセットやカレンダー規則の参照が必要だが、EL式単体では取得できない。

実現方法の例：

・スクリプト処理でクライアント/サーバーからユーザーのタイムゾーンを取得し、`q_now_utc` をローカルに変換して次回0:00を算出し、`q_next_local_midnight` に設定する。
・代替案として、数値型のUTCオフセット項目（例：`q_utc_offset_minutes` 数値型）を追加し、その分だけ加減算してローカル0:00相当を近似計算する（ただしDST切替時には誤差が生じ得る）。
```

### 8. 日付型：複数日付の比較で締切を決めたい

#### 質問

```
ワークフローアプリには、以下のデータ項目がある。

プロジェクト1の開始日
　変数型：日付型
　フィールド名：q_date1

プロジェクト2の開始日
　変数型：日付型
　フィールド名：q_date2

プロジェクト3の開始日
　変数型：日付型
　フィールド名：q_date3

プロジェクト締め切り日期
　変数型：日付型
　フィールド名：q_deadline

[データ更新]を使って、3つのプロジェクト開始日の中で最も遅い日付を求め、その日付に1週間を加算した日付を「プロジェクト締切日」として設定したい。
```

説明：比較演算子と三項演算子を利用する例。

#### 回答

```
EL式：#q_date1 >= #q_date2 && #q_date1 >= #q_date3 ? #q_date1?.addDays(7) : (#q_date2 >= #q_date3 ? #q_date2?.addDays(7) : #q_date3?.addDays(7))

設定対象のデータ項目: q_deadline

```

説明：

- この方法では、3つの日付を比較演算子と三項演算子を使って比較し、最も遅い日付を特定してから7日を加算します。
- `&&` は論理AND演算子で、両方の条件が true の場合に true となります。
